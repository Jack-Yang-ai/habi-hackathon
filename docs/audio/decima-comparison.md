# Decima-small 研究对照

2026-10-15，在 Mac CPU、2 线程、ONNX INT8 上直接运行 122M Decima-small。代码固定 commit `0ab6f2164abb34caa749f31ac643801d1b4b03b7`；模型和 tokenizer 的完整 SHA-256 记录在结果 JSON。全程无规则覆盖、无生产后端提交、无麦克风和手机操作。

| 输入格式 | 相同 18 条合成开发集的 raw top 标签一致数 | 暖态中位 / 最慢耗时 |
|---|---:|---:|
| 较长中文问题 + 中文选项 + JSON 状态 | 3 / 18 | 26.67 / 34.88 ms |
| 短英文问题 + 短英文选项 + Message 中文原话 / Previous 最近对话 | 9 / 18 | 9.83 / 28.12 ms |

第二版去掉两个必须依赖被省略身份元数据的样例后，为 9 / 16。两版均是小型人工合成开发集；第二版是在看到初测后修改提示的对照，不是独立准确率评估。身份和媒体来源仍须外部门控。

短英文输入改善了天气、吃药、开放时间等部分负例，但仍出现：

- “你要不要吃？”判成拒绝，模型最高分约 0.975。
- “好啊，走吧”加上一句吃饭邀请，仍判成拒绝，约 0.954。
- “明天我们去吃火锅吧”判成马上吃，约 0.329。
- “开饭时间早上9点至下午5点。”判成马上吃，约 0.266。
- “他马上去吃午饭”判成马上吃，约 0.394。

原版的状态最多 101 / 512 tokens、选项 43–50 / 64 tokens，没有静默截断。结果显示当前用餐任务对格式敏感，且有高分错误；这些分数不能当作该产品领域已校准的置信度。

初测保存在 `output/validation/decima-context.json`，短格式对照保存在 `output/validation/decima-context-short-prompt.json`。两份文件均包含完整问题、选项、实际输入、逐项原始分布、模型载入时间、每次耗时与内存口径。复现短格式：

```sh
.tools/decision-venv/bin/python -m audio.compare_decima_context --format short
```

当前仅作为研究对照，不选作产品商用默认。作者对训练数据中的非商用条款有披露，详见本地上游 `.tools/decima/release/LICENSING.md`。
