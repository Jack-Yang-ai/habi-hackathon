# 实施边界与分工

## 已确认的产品约束

- 随身自动拍照记录为主，轻提醒为辅。
- 背屏优先，IP 可以对话、在 App 内主动发动态；背屏展示姿态和动作，省略动态摘要。
- 养成围绕相处、偏好、共同经历和虚拟小屋。食量、体重和漏记不作为惩罚依据。
- 识别食物、估计份量、判断实际摄入分别处理，不将识别菜名写成测得热量。
- 正常模式无虚构餐食；演示与真实持久数据隔离。

## 三个可替换层

1. **设备层**：XIAO 固件与 Android / 厂商背屏适配。独立编译、独立回执。
2. **应用与服务层**：照片持久化、候选餐、版本化更正、模型分析、IP 记忆和动态。
3. **表现层**：本地 React 前端、Step Studio 生成页面、17×23 点阵 IP 场景。统一使用明确的状态与事件。

底层与 Studio 并行，父任务维护接口、数据模型与集成；从首个可运行页面开始联调。Studio 原型能否导出、导出内容能否本地构建分别检查。不能导出时，保留已确认交互与素材，由本地工程承接。

## 第一条验收链路

当前手机增量：连续录音 → 本地VAD/SenseVoice/Decider → 准备态线索 → ESP32首图窗口 → Step视觉 → 按需补拍。准备态不等于已进食，模型原始猜测作辅助；实测与硬件未完成部分见 `docs/device/PHONE_PIPELINE.md`。

照片来源有明确身份 → 服务器持久回执 → 候选餐合并 → 用户确认实际食量 → 记录更新 → IP 场景切换 → 有来源动态 → 动态回复。

以下证据分别记录：API 夹具、真实页面交互、手机前屏、背屏厂商状态、背屏肉眼、开发板真实拍摄、拔线运行、长时采集与续航。前一项通过不代表后一项通过。

## 用户提供的经验参考

参考材料：`StepX-root开发经验总结.md`，整理日期 2026-10-15，SHA256：`3c87938c6d610faf514536bb389a89310bef67aafb81dfeefb477df0abc3baf3`。这是其他 APT 项目的有版本范围经验，未原样导入旧实现、旧录音或旧数据库。

落实到本工程的要求：

- UI 生命周期、原生进程存活、有效麦克风采集、文件完成及上传成功各有证据。
- 常规 Android FGS 和独立 UID0 采集分开标记。当前 root 可用性以本机核查为准。
- 权限桥只开放固定动作，避免通用 shell；命令、回执、重试和取消有各自身份。
- 上传确认先于清理设备待传队列；准确身份和指纹不由文件名或时间猜测。
- 背屏现有 custom frame 的所有权和持久化行为要核验；退出只恢复本工程仍拥有的状态。
- 用户停止采集应先于保存、下载和上传；联网工作不阻塞停止。
- Studio 源码、APK 和独立 root 服务是不同交付链，各记版本及指纹。

长时 root 录音、完整 mailbox、异常尾片修复和无人值守后台上传仍需单独实施及验收；本轮普通录音实现不冒充这些能力。
